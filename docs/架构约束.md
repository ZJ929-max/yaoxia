# 架构约束（防屎山规则）

> 由 `tools/arch-check.py` 强制执行，CI/本地提交前跑一次。
> 退出码 1 = 有硬性违规，不允许合并。

## 1. 分层与依赖方向

```
ui ──► apps / channels / provision / di
                 │
                 ▼
             platform ──► core
                 ▲
     delegation ─┘
```

- **core**：零依赖（`Outcome`、`AsyncTaskRunner`、`FailureReporter`）
- **platform**：能力抽象（`Capability`、`ProviderId`、`CapabilityRouter`）
- **delegation / channels / apps / provision**：具体实现，只依赖 core + platform
- **di**：组合根（`ProviderRegistry`、`SelfTest`），允许依赖所有层
- **ui**：只做展示与状态编排，可调 di/apps/provision

**禁止**：`platform → channels`、`core → provision` 这类反向依赖。
需要「注册表」时放进 `di/`，不要塞回 platform。

## 2. 文件体积

| 阈值 | 处理 |
|---|---|
| ≤ 200 行 | 正常 |
| 200–280 行 | 建议拆分（warning） |
| > 280 行 | **硬性失败**，必须拆 |

拆分的正确姿势是**按职责**（主题 / 脚手架 / 单行 / 控制器），不是按行数硬切。

## 3. 死代码

- `staticCompositionLocalOf` 定义后必须至少有 1 处消费，否则视为死代码；
- 删掉的组件要连 import、CompositionLocal、`provides` 一起删；
- 曾经的教训：`LocalCardBackdrop` 定义 + provide 都在，但没有任何读取方。

## 4. 状态与逻辑

- UI 状态放 `ui/*State.kt`（如 `FontController`），**不要**堆进 `AppState`；
- `AppState` 只做组装与转发，不做业务计算；
- 业务规则放 `apps/` `provision/`，可被单测覆盖（`logic` 模块）。

## 5. 第三方边界

- 依赖必须走镜像（阿里云 Maven / jsDelivr / ghproxy）；
- 引入新库前先看许可证（见 `docs/ATTRIBUTION.md`），GPL 代码禁止入仓；
- 库的私有语义（如 Backdrop 的 `layerBackdrop` 必须挂在背景节点）要写进注释。

## 6. 提交前自检

```bash
python3 tools/arch-check.py     # 架构体检
./gradlew :logic:test           # 纯逻辑单测
adb shell am start -n com.opensandbox.dhizuku/.ui.MainActivity --es action selftest
adb logcat -d | grep YaoxiaTest # 全链路 9/9
```
